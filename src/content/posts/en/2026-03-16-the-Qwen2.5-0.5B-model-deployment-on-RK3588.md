This article provides a detailed study and summary of Rockchip's RKLLM tool and its official related guidance documents, documenting the complete process and precautions for adapting the lightweight large language model Qwen2.5-0.5B to the RK3588.

Overall, deploying an LLM on the Rockchip NPU follows the same core logic and workflow as deploying YOLO: **PC-side model conversion -> pushing the model and libraries to the board -> calling the API to run.** However, for large language model adaptation, the `RKNN-Toolkit2` toolchain is no longer used; instead, the `RKLLM-Toolkit` toolchain, optimized specifically for large language models, is employed.

- RKNN-Toolkit2: Handles Convolutional Neural Networks (CNNs) and simple Transformers (Vision Transformers).
- RKLLM-Toolkit: Specifically handles large language models, supporting weight quantization (W4A16/W8A8) and KV Cache optimization.

The following diagram illustrates the framework of Rockchip's RKLLM Toolkit and its software-hardware application ecosystem, which is similar to RKNN:

![image.png](/images/blog/轻量级LLM模型QWen2.5-0.5B在RK3588上的适配流程记录-1.png)

- RKLLM-Toolkit: Used for model conversion and quantization on the PC.
- RKLLM Runtime: Provides C/C++ programming interfaces for Rockchip NPU platforms, helping users deploy RKLLM models on the NPU and accelerate the execution of LLM applications.
- RKNPU Kernel Driver: Responsible for interacting with the NPU hardware, which can be found in Rockchip's kernel code.

## Environment Setup

Download the rkllm codebase from the rkllm GitHub repository ([airockchip/rknn-llm](https://github.com/airockchip/rknn-llm)).

### PC-Side Environment

Create an independent rkllm environment, navigate to the `rkllm-toolkit/packages` directory within the rknn-llm repository, and install `rkllm-toolkit` along with its dependencies:

```bash
conda create -n rkllm python=3.10
conda activate rkllm
pip install -r requirements.txt
pip install rkllm_toolkit-1.2.3-cp310-cp310-linux_x86_64.whl
```

### Board-Side Environment

For running LLMs on the Rockchip NPU, the board-side mainly requires support for the NPU driver and the `librkllmrt.so` shared library (located under `rkllm-runtime/Linux/librkllm_api/aarch64`).

The NPU driver requires version v0.9.8 or higher. You can check whether your board's driver meets the requirement using the following command; otherwise, you will need to recompile the kernel:

```bash
cat@lubancat:~/qwen2.5$ sudo cat /sys/kernel/debug/rknpu/version
RKNPU driver: v0.9.8
```

## Downloading the Model File and Inference Testing on PC

Use `transformers` to download the Qwen2.5-0.5B model files from Hugging Face and perform a local inference test on your PC to verify the integrity of the downloaded files:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

# Model path; will automatically download from HuggingFace when executed (approx. 1GB)
model_name = "Qwen/Qwen2.5-0.5B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name,
    torch_dtype="auto",  # Automatic precision is recommended for PC-side inference
    device_map="auto"    # Automatically uses GPU if available, otherwise falls back to CPU
)

# Prepare conversation
prompt = "你好，请自我介绍一下。"
messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": prompt}
]

# Format Prompt
text = tokenizer.apply_chat_template(
    messages,
    tokenize=False,
    add_generation_prompt=True
)

model_inputs = tokenizer([text], return_tensors="pt").to(model.device)

# Generate response
print("--- 模型输出 ---")
generated_ids = model.generate(
    **model_inputs,
    max_new_tokens=512,
    do_sample=True,
    temperature=0.7
)
response = tokenizer.batch_decode(generated_ids, skip_special_tokens=True)[0]
print(response)
```

Slow download speeds from Hugging Face can be resolved by setting a domestic mirror. Set the environment variables before running the download script above:

```bash
$env:HF_ENDPOINT = "https://hf-mirror.com"     # Windows
export HF_ENDPOINT=https://hf-mirror.com       # Linux
```

## Model Conversion

Using the `rkllm-toolkit` package installed in the environment setup section, execute the following code to complete model conversion:

```python
from rkllm.api import RKLLM
import os

model_path = "/home/pavelhan/models/qwen2.5-0.5B" # Points to the local folder of the model files downloaded earlier
output_path = "./qwen2_5_0_5b_w4a16.rkllm"

rkllm = RKLLM()

# 1. Load model
print("Loading model from HuggingFace format...")
ret = rkllm.load_huggingface(model=model_path)
if ret != 0:
    print("Load model failed!"); exit(ret)

# 2. Model building configuration
print("Building RKLLM model...")
ret = rkllm.build(
    do_quantization=True,
    optimization_level=1,
    #quantized_dtype='w4a16', # 4-bit weights, 16-bit activations; not supported by RK3588
    quantized_dtype='w8a8', # 8-bit weights, 8-bit activations; supported by RK3588
    target_platform='rk3588'
)
if ret != 0:
    print("Build model failed!"); exit(ret)

# 3. Export model
print(f"Exporting to {output_path}...")
ret = rkllm.export_rkllm(output_path)
if ret != 0:
    print("Export failed!"); exit(ret)

print("Conversion completed successfully!")
```

> Note: Regarding quantization type support, the RK3588 does not support `w4a16`, but supports four types: `w8a8`, `w8a8_g128`, `w8a8_g256`, and `w8a8_g512`.

After the model conversion finishes, a `qwen2_5_0_5b_w8a8.rkllm` file of around 800MB will be generated in the current directory.

## Board-Side Compilation and Inference

Once the board-side model conversion is complete, the next step is to prepare the board-side inference code:

```c++
#include <iostream>
#include <string>
#include <vector>
#include <cstring>
#include "rkllm.h"

// Callback function: handles tokens generated by the model
int callback(RKLLMResult* result, void* userdata, LLMCallState state) {
    if (state == RKLLM_RUN_FINISH) {
        // Print performance statistics after inference ends
    	std::cout << "\n[Performance Statistics]" << std::endl;
		std::cout << "Peak Memory Usage: " << result->perf.memory_usage_mb << " MB" << std::endl;
		std::cout << "Prefill Time: " << result->perf.prefill_time_ms << " ms" << std::endl;
    } else if (state == RKLLM_RUN_ERROR) {
        std::cerr << "RKLLM run error!" << std::endl;
    } else if (state == RKLLM_RUN_NORMAL) {
        // In version 1.2.3, generated content is passed back via result->text
        if (result && result->text) {
            std::cout << result->text << std::flush;
        }
    }
    // Return 0 to inform the SDK to continue the inference process
    return 0;
}

int main(int argc, char** argv) {
    if (argc < 2) {
        std::cout << "Usage: ./rkllm_demo <model_path>" << std::endl;
        return -1;
    }

    std::string model_path = argv[1];

    // 1. Configure RKLLM parameters
    RKLLMParam param = rkllm_createDefaultParam();
    param.model_path = model_path.c_str();
    param.max_context_len = 1024;
    param.max_new_tokens = 256;
    param.top_k = 1;
    param.top_p = 0.9;
    param.temperature = 0.8;

    // 2. Initialize model handle
    LLMHandle handle = nullptr;
    std::cout << "Initializing RKLLM with model: " << model_path << " ..." << std::endl;
    int ret = rkllm_init(&handle, &param, callback);
    if (ret != 0) {
        std::cerr << "rkllm_init failed! ret=" << ret << std::endl;
        return -1;
    }
    std::cout << "RKLLM Initialized Success!" << std::endl;

    // 3. Construct input data (crucial correction point)
    std::string prompt_str = "<|im_start|>system\nYou are a helpful assistant.<|im_end|>\n"
                             "<|im_start|>user\n请介绍一下陕西省省会城市的相关资料。<|im_end|>\n"
                             "<|im_start|>assistant\n";

    RKLLMInput rkllm_input;
    memset(&rkllm_input, 0, sizeof(RKLLMInput));
    rkllm_input.input_type = RKLLM_INPUT_PROMPT;
    rkllm_input.role = "user";
    rkllm_input.prompt_input = prompt_str.c_str();
    rkllm_input.enable_thinking = false;         // Qwen2.5-0.5B is not a deep thinking model, set to false

    // 4. Configure inference parameters
    RKLLMInferParam infer_params;
    memset(&infer_params, 0, sizeof(RKLLMInferParam));
    infer_params.mode = RKLLM_INFER_GENERATE;    // Set to normal generation mode
    infer_params.keep_history = 1;               // Whether to keep KV Cache history

    // 5. Execute inference
    std::cout << "Assistant: " << std::flush;
    rkllm_run(handle, &rkllm_input, &infer_params, nullptr);

    // 6. Destroy handle and release resources
    rkllm_destroy(handle);
    return 0;
}
```

For cross-compiling the board-side inference code, you can follow standard development methods by compiling on the PC and then uploading to the board for execution. Therefore, things became much simpler: you can directly upload the board-side inference source file (`main.cpp`), header file (`rkllm.h`), shared library (`librkllmrt.so`), and the converted board-side model to the board, and compile directly using `g++` in the board's Debian system:

```bash
g++ -O3 main.cpp -I. -L. -lrkllmrt -lpthread -lm -ldl -o rkllm_demo
export LD_LIBRARY_PATH=.:$LD_LIBRARY_PATH
./rkllm_demo ./qwen2_5_0_5b_w8a8.rkllm
```

As can be seen, this model is now up and running on the RK3588. However, the content generated by a 0.5B-scale LLM still has some noticeable issues: not only does it casually "solve" the Xi'an-Xianyang integration issue that has troubled Xi'an's development for 30 years, but it also mistakenly attributes Yulin's data to Xianyang.

Regarding memory consumption during inference, this model only uses about 680MB of memory. Given that the board-side converted model file itself is already 800MB, this indicates that Rockchip RKLLM does not load the entire model file completely into memory during execution, but rather loads it on-demand. This makes it extremely practical for memory-constrained applications like embedded devices.
