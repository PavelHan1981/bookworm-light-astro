The goal of this article series is to help non-AI professionals understand the basic concepts of AI and large language models in practical applications. By deeply understanding and clarifying these concepts, we aim to build a knowledge structure regarding the working mechanisms, workflows, and application frameworks of large models, enabling us to better utilize AI in our daily lives and work.

## RAG

RAG (Retrieval-Augmented Generation) is a novel generative model that combines large pre-trained language models with knowledge retrieval technology, offering new perspectives for addressing various challenges in large model application development.

### Issues with Generative Large Models

Large models do not possess the comprehensive knowledge required to answer specific questions in continuously changing environments. For instance, the pre-training corpus of early versions like ChatGPT 3.5 cutoff in 2021, meaning the model cannot accurately output factual answers about events after 2021. This is precisely the knowledge-updating dilemma faced by modern large models.

In fact, updating the base model's knowledge base for a large model is an extremely difficult task. First, the quality of the pre-training data must be guaranteed; second, models with updated knowledge bases typically require retraining—at least mixing new and old data in a certain proportion rather than using only new data, otherwise catastrophic forgetting will occur. In short, the knowledge-updating problem of large models will remain a major pain point and a subject worthy of continuous research.

RAG can effectively solve the above problems. **This framework allows models to access information beyond the scope of their training data**, enabling them to leverage external, more specialized, and accurate knowledge provided by retrieval during each generation, thereby better answering user queries.

### The Workflow of RAG

The complete workflow of RAG primarily involves 3 stages: data preparation, data retrieval (recall), and answer generation. The quality of the output largely depends on data quality and retrieval strategies.

- The data preparation stage includes identifying data sources, extracting data from those sources, cleaning the data, and storing it in a database.
- The data retrieval stage involves querying relevant data from the database based on the user's input conditions.
- The answer generation stage utilizes the retrieved data and the user's input query to generate the output result.

The diagram below illustrates the workflow of a RAG system implemented using an LLM and a local knowledge base database (where question-related knowledge and information are already stored locally).

![image.png](/images/blog/非专业人士的AI课4：-1.png)

- 1. The user inputs a query to the RAG system via a prompt.
- 2. The system decomposes the user's question and first calls the search engine to retrieve knowledge snippets related to the query from the local knowledge base database.
- 3-4. The retrieved knowledge snippets are placed into the user input prompt as context.
- Finally, the LLM parses the user's query and the contextual information to generate a text-based answer.

> Compared to direct inference output from large models, RAG systems have another prominent advantage: the traceability of their output information. As is well known, in the field of large models, most models are based on the Transformer decoder architecture, leading to the unexplainability of their generated results. Combined with a large language model, a RAG system not only provides the answer but also provides citation links for information traceability. Therefore, compared to pure large model generation, RAG offers stronger interpretability.

In fact, the large models we use today generally provide web-searching capabilities, and this web-searching feature is essentially an implementation of RAG. Before answering a question, it first cooperates with a search engine to query web pages with reference value, processes and retrieves the webpage content, and then puts the relevant retrieved content into the prompt context of the large model, ultimately returning the result generated by the large model.

### Comparison Between RAG and Fine-Tuning

Model fine-tuning refers to the process of training a model on a specific task using a certain amount of data. Fine-tuning on a specific dataset can improve the model's performance on that dataset. If there is a sufficiently large supervised dataset that does not change, fine-tuning is an excellent approach. However, if the dataset is dynamic, the model must be continually retrained to keep up with data changes. In this scenario, using a fine-tuning approach incurs high costs and results in very poor system flexibility.

![image.png](/images/blog/非专业人士的AI课4：-4.png)

Overall, RAG sits in the middle of the difficulty chain for large model applications. It is neither as difficult as retraining, building models from scratch, or fine-tuning, nor as easy as directly querying a large model through simple prompt engineering. It overcomes the three major drawbacks of direct model fine-tuning—high cost, difficulty in updating information, and lack of observability. In comparison, RAG is lower in cost because it requires no training; its data is always up-to-date because it is fetched in real-time; and its results are more reliable because the retrieved documents can be displayed.
