## taxonomy 修复 + 停建 noindex 路由（commit d05b058，已推送）

### 根因：slugify 吃掉 CJK

`src/lib/utils/textConverter.ts` 的 `slugify` 用 `[^\w\s-]` 过滤，中文全被剥离：

- `slugify("网络安全") === ""` → `getTaxonomy` 的 `filter(c => c !== "")` 把它丢掉
  → **11 个中文分类页从未生成**（网络安全/音视频/硬件/软件工程/物联网/嵌入式/
  移动通信/其他/无线通信/全栈开发/云平台）。ASCII 名字的 AI/WiFi/Bluetooth/Linux/Tech
  侥幸生成了，`/categories/ai` 独吞 83 篇。
- 文章页模板用同一个函数拼链接 → **225 篇中文文章里 158 篇的分类/标签链接退化成
  `href="/categories/"`**（空链接，落到索引页）。中文内容主题聚类内链等于零。
- 反向：taxonomy 只从 zh 收集（`getSinglePage` 默认 `lang="zh"`），英文文章引用 20 个
  英文独有分类 + 30 个英文独有标签 → 50 个 URL 全 404，对应 GSC「Not found 46」。

### 修法

- 新增 `slugifyTaxonomy`：字符集 `[^\p{Letter}\p{Number}\s_-]` /gu，保留 Unicode 字母。
  **`slugify` 保持原样**——作者 slug 等 ASCII 场景不受影响，别全局替换。
- 新增 `safeDecode`：Astro 路由参数可能已解码也可能仍是百分号编码，二次解码遇裸 `%` 会抛异常。
- 调用点：taxonomyParser.astro / taxonomyFilter.ts / Posts.astro / PostSingle.astro /
  SimilarPosts.astro / SearchBar.tsx / authors/[single].astro / zh/index.astro（**首页
  有自己的内联分类链接，容易漏**）。
- 分类/标签页 H1+title 改用 frontmatter 原始写法（原来 `humanize("ai")` → "Ai"，
  `humanize("audio-video")` → "Audio Video"），并补 description。
- canonical 不要手拼 `${Astro.site}...`（base_url 无尾斜杠会拼错），用 Base 默认的
  `${config.site.base_url}${Astro.url.pathname}` 即可，中文路径会自动百分号编码。

## 修复 description 失效（P0-1 闭环）

### 根因：Notion rich_text 分片只取 [0]

`sync.mjs:253`（原）`page.properties.summary?.rich_text?.[0]?.plain_text`。

Notion 的 `rich_text` 是**片段数组**：同一段文字只要有格式差异（链接、加粗、行内代码、
甚至光标编辑留下的分片）就会被拆开。取 `[0]` 只拿到首片 → description 被截成单字。

**实证**：`2026-07-01-mmWave` 正文首段是 `在 [一文搞懂mmWave...](url)一文中，...`，
链接边界把 rich_text 切成 `["在", "一文搞懂...", "一文中，..."]`，`[0]` = `"在"`。
另有 5 篇 `""` 是 summary 属性本身为空。

### sync.mjs 改动（注意：该文件在 `.gitignore:30`，改动不进版本控制）

1. 新增 `joinRichText` / `joinTitle`，`.map(t => t.plain_text).join("")`，
   替换 title / slug / description 三处 `[0]` 取值。
2. description 兜底：`< 60` 字符时从正文首段剥掉代码块/图片/链接语法后截 150 字符；
   仍不足则 warn 提示去 Notion 补 summary。
3. frontmatter 新增 `dateModified`（与 `last_edited_time` 并存）——之前只写
   `last_edited_time` 而 `content.config.ts` 只认 `dateModified`，导致更新时间信号全丢。
4. `image` 不再硬编码 `default.jpg`，改为读取已有 frontmatter 保留自定义封面。
5. `escapeYaml`：同时转义反斜杠 + 双引号 + 折叠换行（原来只转义 `"`）。

### 内容修复

- 中文 51 篇（12 条 P0 + 39 条 P1）全部重写，长度 88–154 字符，中位数 92。
  **做法**：导出「标题 + H2 + 首段」骨架后逐篇手写，不编造，只基于原文事实归纳。
  映射表 `.workbuddy/outputs/desc_fix_map.json`，回填脚本 `apply_desc_fix_v2.py`。
- 英文 9 篇同源失效值（`""` / `"In"` / `"Previously in"` / `"Amazon Bedrock"`）
  一并重写为英文版，长度 231–283 字符。映射 `desc_fix_map_en.json`。
- 校验：中英文各 225 篇，YAML 错误 0，`<50` 字符 0。

### 踩坑：跨行双引号标量被腰斩

首版 `apply_desc_fix.py` 只替换 `description:` 那一行。但有 3 篇
（duplexer / SDcard / CMD6）原本是**合法但跨行**的双引号标量：

```yaml
description: "在SD协议中...其复杂性体现在：
- 同一个命令...          ← 这些是 description 的续行，不是正文
"

```

只换首行 → 残留续行 + 悬空 `"` → YAML 非法（gray-matter 报
`end of the stream or a document separator is expected`）。

**正确做法**（`apply_desc_fix_v2.py`）：向后一直吞到「下一个顶层 YAML 键」
（`^[A-Za-z_][\w-]*\s*:`）之前再替换。**改 frontmatter 字段前必须先探测它是否为
跨行标量**，不能假设单行。

## 修复 sync.mjs 图片下载静默失败（downloadImage）

### 根因是两层，不是一层

1. `downloadImage()` **失败只 `console.error` 且无返回值**，调用方无条件执行
   `mdString.replace(imgUrl, "/images/blog/...")` → 正文指向不存在的文件，构建期不报错。
2. 原来的 `withRetry()` **管不到这个场景**：它只认 `ECONNRESET/ETIMEDOUT/ENOTFOUND`
   这类网络层错误；Notion S3 返回的 403 是 axios 的 HTTP 错误（message
   `Request failed with status code 403`），会被判定"不可重试"直接抛出，**一次都不重试**。
   这正是这次 5 张图全 403 却没有任何重试记录的原因。

### 改法（三处）

- `downloadImage(url, localPath, maxAttempts = 3)` → 返回 `true/false`：
  自带退避重试（1.5s/3s）、`response.data.on('error')` 也 reject（否则流断开会挂住）、
  写完校验 `statSync().size > 0`（空文件也算失败）、失败时 `unlinkSync` 清理残文件
  （否则下次走到 `existsSync` 分支会被误判为"已存在"）。
- 调用点：`if (downloaded) 改写 URL; else { failedImages.push(...); 保留原 URL }`。
- 循环结束后：若有失败，打印清单 + 「原始地址约 1 小时后失效」提醒。

### 验证（4 组，全部实测非语法检查）

| 用例 | 结果 |
|---|---|
| 正常 URL | `true`，24895 bytes |
| 404 | `false`，3 次重试（1.5s/3s），**无残留文件** |
| DNS 失败 | `false`，3 次重试，无残留文件 |
| **真实 Notion S3 × 5 张** | `5/5 true`，字节数与已发布版本完全一致 |
| 冒烟：`sync.mjs --title eSIM`（不加 --force） | 正确跳过，零文件改动 |

测试脚本：`.workbuddy/outputs/test_download_image.mjs`（从 sync.mjs 抽真实函数执行，
不复制代码）、`test_notion_s3.mjs`（真拉 Notion 块的预签名 URL）。

### 注意：sync.mjs 在 .gitignore:30，这次改动同样不进版本控制

换机器/重装环境会丢。要么纳入 git（敏感值走 .env，该文件已有 dotenv），
要么单独备份。

## 全站启用 LaTeX 公式渲染（remark-math + rehype-katex）

### 之前为什么不渲染

`astro.config.mjs` 里 `remarkMath` 被**注释掉**、`rehypePlugins: []` 为空。
三个包一直在 `package.json` 里装好了（remark-math 6 / rehype-katex 7 / katex 0.16.45），
只是从来没接上 → 226 篇文章里的 `$$...$$` 和 `$...$` 全部原样输出。

### 先量化再动手（关键）

用 `unified + remarkParse + remarkMath` 复刻站点解析，再用 KaTeX 逐个编译：

| 指标 | 数值 |
|---|---|
| 含公式文件 | 103 |
| 公式节点 | **2069**（display 220 + inline 1849）|
| 编译失败 | **0** |

结论：`rehype-katex` 默认 `throwOnError: false` + `strict: 'ignore'`，
即使有坏公式也只是该节点渲染成红字，**不会炸构建**。所以「能编译」≠「都是真公式」，
必须再做一轮「可疑节点」筛查：

- 含中文：14 个 → 其中 13 个是合法 `\text{当 } x \text{ 小于0}` 这类，只有 1 个是误判
- 纯数字：12 个 → 全是表格里的 `$0$` `$1$`，合法
- **真问题 5 处**：`6-7$…10$` 两个价格被配成公式（1 处）、公式里写全角标点（4 处）

### 改法

1. `astro.config.mjs`：放开 `remarkMath`，`rehypePlugins: [rehypeKatex]`（两个 import 本来就有）
2. `PostSingle.astro`：`import "katex/dist/katex.min.css"`
   —— **只在这里引**，首页/列表页不背 KaTeX CSS（已实测首页只引 Base.css，
   文章页多引 PostSingle.css）
3. 修 5 处内容：价格 `$` → `\$`；公式内 `，（）` → `, ()`

### 验证结果

- 构建成功，zh/en 各 228 页
- **全站 0 个 `katex-error`**
- 102 个页面渲染出公式（mmWave 那篇 276 个 katex 节点、9 个 display 块）
- 价格页 `$` 原样保留，未被吃掉
- 字体：59 个 KaTeX 字体文件自动落到 `dist/_astro`，CSS 里 url 已重写为 hash 路径
- **输出含 MathML**（`<math xmlns=...>` 89 处）+ 零客户端 JS
  → 对 AI 抓取和无障碍都友好，这是 SSR 编译的相对优势

### 写公式的规矩（后续写作要守）

- 行内 `$...$`，块级 `$$...$$` 单独成行
- **公式内禁用全角标点**（，。、（）），KaTeX 会渲染错位
- **正文里字面量 `$`（价格、shell 变量）必须写 `\$`**，否则会和相邻 `$` 配对
- 公式内要写中文只能包在 `\text{}` 里
- 代码块和行内 code 里的 `$` 安全，remark-math 不解析
