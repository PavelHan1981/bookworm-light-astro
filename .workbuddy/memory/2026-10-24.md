## taxonomy 修复 + 停建 noindex 路由（commit d05b058，已推送）

### 根因：slugify 吃掉 CJK

`src/lib/utils/textConverter.ts` 的 `slugify` 用 `[^\w\s-]` 过滤，中文全被剥离：

- `slugify("网络安全") === ""` → `getTaxonomy` 的 `filter(c => c !== "")` 把它丢掉
  → **11 个中文分类页从未生成**（网络安全/音视频/硬件/软件工程/物联网/嵌入式/
  移动通信/其他/无线通信/全栈开发/云平台）。ASCII 名字的 AI/WiFi/Bluetooth/Linux/Tech
  侥幸生成了，`/categories/ai` 独吞 83 篇。
- 文章页模板用同一个函数拼链接 → **225 篇中文文章里 158 篇的分类/标签链接退化成
  `href="/categories/"`**（空链接，落到索引页）。中文内容主题聚类内链等于零。
- 反向：taxonomy 只从 zh 收集（`getSinglePage` 默认 `lang="zh"`），英文文章引用 20 个
  英文独有分类 + 30 个英文独有标签 → 50 个 URL 全 404，对应 GSC「Not found 46」。

### 修法

- 新增 `slugifyTaxonomy`：字符集 `[^\p{Letter}\p{Number}\s_-]` /gu，保留 Unicode 字母。
  **`slugify` 保持原样**——作者 slug 等 ASCII 场景不受影响，别全局替换。
- 新增 `safeDecode`：Astro 路由参数可能已解码也可能仍是百分号编码，二次解码遇裸 `%` 会抛异常。
- 调用点：taxonomyParser.astro / taxonomyFilter.ts / Posts.astro / PostSingle.astro /
  SimilarPosts.astro / SearchBar.tsx / authors/[single].astro / zh/index.astro（**首页
  有自己的内联分类链接，容易漏**）。
- 分类/标签页 H1+title 改用 frontmatter 原始写法（原来 `humanize("ai")` → "Ai"，
  `humanize("audio-video")` → "Audio Video"），并补 description。
- canonical 不要手拼 `${Astro.site}...`（base_url 无尾斜杠会拼错），用 Base 默认的
  `${config.site.base_url}${Astro.url.pathname}` 即可，中文路径会自动百分号编码。

## 撤回「删除英文站」（commit f036513）

### 判断错误复盘

上一轮我把 245 个 noindex 的 `/en` 页面当成「纯抓取浪费」删掉了。错在**拿当前的 SEO 策略
（en 暂时 noindex）当成了产品目标**。Pavel 的诉求是站点做成中英双语，英文是要长期存在的
一部分，noindex 只是权宜之计。**教训：动「删一整块内容」之前，先确认这块内容是不是产品的
组成部分，而不是只看它当下的索引状态。** 页面可回滚（内容一直在 `src/content/posts/en/`），
但这个决策本身应该先问。

### 恢复内容

`git checkout 81bfddd -- src/pages/en src/layouts/components/LanguageSwitcher.astro
public/llms-en.txt public/llms-full-en.txt`，再恢复 generate-llms.mjs 的英文生成、
robots.txt 的英文入口、`_redirects` 去掉 /en 规则。
`config.settings.en_indexable: false → true`（Base 统一输出 noindex、sitemap 自动剔除 /en，
所以这一个开关就能整体切换英文是否参与索引）。

### 双语 taxonomy（关键架构决定）

英文分类名和中文分类名完全不同（Hardware vs 硬件），上一轮修好的 taxonomy 只服务中文，
英文页面沿用会 404。最终定为**两侧对称**：

```
/zh/article/{slug}    ↔  /en/article/{slug}
/zh/categories/{slug} ↔  /en/categories/{slug}
/zh/tags/{slug}       ↔  /en/tags/{slug}
```

- `taxonomyParser` 加 `lang` 参数；`taxonomyBase(lang, kind)` 统一产出前缀
  （`src/lib/utils/taxonomyUrl.ts`，同时导出 `taxonomyLang(postId)`）
- 新增 `src/pages/en/{categories,tags}/{index,[slug]}.astro`
- 中文 taxonomy 从根路径迁到 `/zh/*`，`/categories*`、`/tags*` 全部 301 兜住

**踩过的坑**：一开始图省事把中文 taxonomy 留在根路径 `/categories`，结果 LanguageSwitcher
用 `"/zh" + pathname` 拼出了 `/zh/categories/ai` 这种不存在的地址 —— 一次构建 181 个死链。
对称结构才是对的，非对称会让所有「按前缀映射」的逻辑失效。

### LanguageSwitcher 的三条规则

1. 按 `/zh` `/en` 前缀直接替换
2. 分类/标签页 → 跳到另一语言的 taxonomy **索引页**（两侧 slug 集合不同，无法一一映射）
3. `/authors`、`/search` 只有中文版 → 不渲染切换器，否则每页产出 `/en/authors/xxx` 死链

### 顺手修的

- `SimilarPosts.astro` 用 `/${post.id}` 拼链接（id 可能带扩展名）→ 改为与 Posts.astro 一致
- 两篇英文 slug 拼错（`uboot-uboot-ufu`、`SD-SDIO-EMMMC`）→ 与中文对齐 + 301，
  否则 zh↔en hreflang 对不上
- 英文版 UVC 文章的 `/0e7651f9...` 坏链接（中文版上一轮已修，英文版漏了）

### 结果

683 页 / noindex 32（全是分页 + 工具页）/ 可索引 651；sitemap 648（zh 315 + en 331 +
authors 2）；内链死链 0；hreflang 目标缺失 0；英文首页 H1 + 2452 字符正文 + 40 条内链。
