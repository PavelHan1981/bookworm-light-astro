# 2026-10-23

## pavelhan.tech Google 零流量诊断

站点：Astro(bookworm-light) + Cloudflare Workers 静态资源，双语 `/zh` + `/en`，226 篇中文原创 + 226 篇 Gemini 机翻英文。

**根因（P0）**
1. **canonical ↔ 307 死循环**：`config.json` 里 `trailing_slash: false`，但 CF Workers 静态资源默认 `auto-trailing-slash` 会给 `index.html` 补尾斜杠。结果 sitemap 546 条 URL、内部链接、hreflang、canonical **全部无尾斜杠** → 访问时 307 跳到带斜杠地址 → 该页 canonical 又指回无斜杠地址。全站 canonical 指向重定向 URL，Google 判为规范网页冲突/已通过重定向排除，故零索引。
2. **首页 `noindex,nofollow` + JS 跳转**：`src/pages/index.astro` 用 `<Base noindex={true}>` 并 `location.replace("/"+targetLang)`。首页本应 301 到 `/zh` 或直接渲染中文内容。
3. **无任何 Google Search Console 验证文件**（`public/` 下无 google 验证文件），sitemap 从未主动提交。

**次要问题**
- `/en/` 226 篇全机翻（`translate_all.mjs` 用 Gemini），属 Google spam policy 的 auto-translated content，难以排名且可能拖累整站。
- sitemap 混入 32 条 noindex 分页（`/en|zh/article/page/N`），filter 只排了 `/page/` 和 `/article/`。
- sitemap 2 条 404：文件名含 Unicode 右单引号 `’`（`2025-03-10-What's-MCP-in-LLM-modal`）。
- `lastmod: new Date()` 导致 546 条 URL 的 lastmod 全为构建时间。
- 242 个无语言前缀旧路径 `/article/xxx` 全部 noindex 但未 301 到 `/zh` 版本，权重白丢。

**重定向链实测**：`/zh/article/slug` → 307 → `/zh/article/slug/` → 200；后者 canonical 指向前者。
另：`http://` 返回 403（需复核 CF 的 Always Use HTTPS）；`www` 301 到裸域正常；404 正常返回 404；JSON-LD 完整（BlogPosting/BreadcrumbList/Organization/Person）。

## 第二轮：lastmod 修复 + slug 规范化的失败记录

### 已完成：sitemap lastmod 改为真实内容日期（commit d9c6bbb，已上线验证）

`astro.config.mjs` 去掉顶层 `lastmod: new Date()`，改用 `serialize(item)` 逐条写入。
新增 `buildLastmodMap()` 扫描 `src/content/posts/{zh,en}/*.md`，从 frontmatter 取
`dateModified || date` 建立 `slug → 日期` 映射；匹配不上的（索引页、分类页、标签页）
直接 `delete item.lastmod`。

**关键坑：绝对不能用文件 mtime。** CI 构建 checkout 会把所有文件 mtime 重置为构建时刻，
等于把全站 lastmod 写成"今天"。

线上验证结果：284 条 URL / **217 个不同 lastmod 值**（改前是 1 个）/ 59 条无 lastmod；
抽样 `2020-05-07` 文章 lastmod 正是 `2020-05-07T00:00:00.000Z`。

### 已修正的误判

- 此前记为「2 条 sitemap URL 是 404」**是错的**。那篇 MCP 文章 `%E2%80%99` 编码形式
  线上返回 **200**，只是本地校验脚本没做 URL decode 才误报 404。
- 排除了「CF 构建缓存 / content layer 缓存」假说：`git show` 证明所有提交里 slug
  一直是 `What’s`，从未变成 ASCII，所以「新 slug 404」不是构建问题，而是前提本身就错。

### 未完成：MCP 文章 slug 的 ASCII 规范化（已回退）

尝试把 `What’s`（U+2019）改成 ASCII `Whats`：文件名 `git mv` 成功，但 frontmatter
的 slug 替换没有真正落盘（git 记录为 100% 相似度的纯 rename，正是内容未变的证据）。
结果 `_redirects` 里那条 301 把正常页面指向了不存在的 URL，导致文章短暂不可访问。

处置：删除 `_redirects` 中的 MCP 301 规则，把 slug 回退为 `What’s`，页面恢复 200。
当前状态为 **ASCII 文件名 + 原始 `What’s` slug**，功能正常（Astro 用 slug 决定 URL，
文件名不影响路由）。

**收益判断**：URL 含 `%E2%80%99` 不影响索引与排名，继续改动的风险（301 指向 404）
大于收益，建议保持现状。若将来确实要规范化，必须在本地构建后确认 `dist/` 下真的
生成了新 slug 目录，再加 301 规则，并先清理 CF 构建缓存。

### 顺手修掉：重复文章

`2023-03-23-the-full-stack...` 与 `2026-03-23-the-full-stack...` 两篇 **md5 完全相同**
（10121 字节），却声明了同一个 slug，其中一篇永远无法生成页面。已 `git rm` 掉 2023 那份
（zh + en 各一个），源文件数 226 → 225。

### 构建命令变更

`package.json` 的 build 改为 `node generate-llms.mjs && astro build --force`
（`--force` 清 content layer 与 content collection 缓存）。

## 第二轮技术 SEO 审计（索引链路修完后的"进去之后"问题）

前一轮解决的是「Google 进不来」，本轮查「进来之后看到什么」。均为实测数据，未改动代码。

**P0**
1. **首页零内容、零 H1**：`src/pages/zh/index.astro` 只有一个名言轮播 + 一句口号。实测 H1=0、H2=0，
   去掉 Header/Footer 后可见文字仅 199 字符（含菜单）。无文章列表、无分类入口 → 站点没有内容锚点，
   内链只靠导航 3 条。
2. **hreflang 单向声明**：en 文章页输出 en/zh/x-default 三条，zh 文章页只输出 zh/x-default 两条。
   hreflang 是双向契约，en→zh 有、zh→en 无 → GSC 报「缺少返回链接」并可能忽略整组。
   且 en 已 noindex，再输出 hreflang 纯属自找警告。修法：en 侧完全移除 hreflang。
3. **分页 `noindex,nofollow`**：`/zh/article/page/N` 实测输出 noindex,nofollow，nofollow 切断
   爬虫沿分页深入文章的路径，应改 `noindex,follow`。

**P1（体积失控，同一根因两处）**
4. `Posts.astro:87` 用 `<p>{plainify(post.body ?? "")}</p>` + CSS `line-clamp-2` 视觉截断，
   **完整正文已进 HTML**。实测：`/categories/ai` 761KB、`/tags/cnn` 400KB、`/zh/article` 列表 172KB。
   修法：服务端截断字符串。
5. `search.astro` 把 `content: item.body` 全量序列化进 props → `/search` **2.8MB**。
   修法：构建时输出 search-index.json，前端 fetch；或只留 title/description/tags。
6. 首页 `<Excerpts client:load />` 为一句自动轮播名言加载 React runtime
   （client.js 185KB + Excerpts.js 7.7KB ≈ 193KB）。可纯 CSS 动画实现，零 JS。
7. 45 个标签页中 15 个只有 1 篇、23 个 ≤2 篇，全部在 sitemap 且可索引（薄内容稀释）。
8. `/zh/elements`（UI 组件演示页）在 sitemap 且可索引。
9. 225 篇文章 **0 篇有 `dateModified`** → sitemap lastmod 全等于发布日期，无更新信号。

**P2**
10. **`<meta charset>` 完全缺失**，只有 `<meta http-equiv="Content-Type">` 且在 head 第 122 行
    （前面已有 GTM/GA inline script）。应改 `<meta charset="utf-8">` 放 head 首位。
11. `<title>` 内容带换行缩进：实际输出 `<title>\n      Pavel Han - 技术博客\n    </title>`。
12. Footer（menu.json）用 `/`、`/article`、`/about`，Header 用 `/zh`、`/zh/article`、`/zh/about`。
    前者 2 条走 301、1 条落在 noindex 页 → 每页白送两次 301。
13. 首页 JSON-LD 只有 WebSite + Organization，缺 ItemList。
14. 死代码：`Base.astro` 导入 `Font` 从未使用，`fontEntries` 算完丢弃；
    Google Fonts 用阻塞式 `<link rel="stylesheet">`。
15. 文章正文 H1 滥用仅 2 篇（`dipolor-antenna` 4 个、`ViT-modal` 1 个），个案，P3。

## GSC 索引报告对账（2026-10-24，只读诊断，未改代码）

用户提供 GSC「Why pages aren't indexed」快照，逐类对账昨天的改动。**结论：7 类里 3 类已解决、
1 类按设计会变大、2 类需时间、1 类（404 ×46）昨天没碰且刚查到根因。**

### 关键新发现：taxonomy（分类/标签）系统双语双向都是坏的

`src/lib/utils/textConverter.ts` 的 `slugify` 用 `[^\w\s-]` 过滤，**中文被全部剥离**：

- `slugify("网络安全")` → `""`（空串）→ `getTaxonomy` 里被 `filter(c => c !== "")` 丢掉
  → **11 个中文分类页从未生成**（网络安全/音视频/硬件/软件工程/物联网/嵌入式/移动通信/
  其他/无线通信/全栈开发/云平台）。只有 ASCII 名字的 AI/WiFi/Bluetooth/Linux/Tech 生成了
  （这也是为什么 `/categories/ai` 有 83 篇、176KB）。
- 文章页模板用同一个 slugify 构造链接 → `href="/categories/"` / `href="/tags/"`
  **空链接**。实测 225 篇中文文章中 **158 篇**含空 taxonomy 链接，全部落到 `/categories/`
  （307 → 索引页），主题聚类内链等于零。
- 反向：`getSinglePage("posts")` 默认 `lang="zh"` → taxonomy 只从中文文章收集；
  而英文章节引用了 20 个英文独有分类 + 30 个英文独有标签（Hardware/Cybersecurity/
  Neural Network Theory…）→ **50 个 URL 全部 404**。GSC 的「Not found (404) = 46」基本就是这批。
